# Bits, Bytes and Integers
- A bit is a 0 or a 1
- A byte is a group of 8 bits
- A word is a group of bits that a processor treats as its natural unit of data: the size of its registers, of a memory address and of the quantity it loads, stores or adds in one instruction. Current processors have 64-bit words, hence 64 bit.

- NumPy integer types are named by their width and signed-ness. For example, `uint8` is an unsigned 8-bit integer, `int16` is a signed 16-bit integer
- On the other hand, Python integers have no fixed width
- Importantly, values outside of NumPy integer types are not rejected, instead they are wrapped around. 141 stored as an `int8` comes out as $141-256=-115$.

There are 3 widths that come up constantly, due to the hardware being built around them: the byte, 32 bits and 64 bits.
- **The byte** is the smallest addressable unit: every location in memory holds one byte and has an address, a number counting the bytes from 0 upwards. Sizes of files and of memory are counted in bytes; a character in ASCII is one byte.
- **Registers** are the few dozen storage slots inside the processor; an instruction operates only on registers, so $a + b$ is: load $a$ from memory into a register, load $b$ into another, add, store the result back. On a 64-bit processor (arm64 on a Mac, x86-64 on CSD3) a register holds 64 bits: one instruction handles an integer up to $2^{64} − 1$ or a float64.
- **Addresses** are also 64 bits wide today, so a program can name $2^{64}$ bytes of memory, equal to 16 $EiB$.

# Memory Sizes
Array size = elements $\times$ bytes per element

So a $10^4\times10^4$ float64 matrix is $10^8$ numbers $\times$ $8$ bytes = $800$ MB

# Real Numbers: IEEE 754
A real number is stored in scientific notation in base 2:
$$
x=(-1)^s \times 1.f\times 2^e
$$
with a sign bit $s$, a fraction $f$ (bits after leading 1, also called mantissa) and an exponent $e$, stored shifted by a constant bias so that the field is a non-negative integer, i.e. it holds $e$ $+$ bias, never $e$ by itself. For a $k$-bit exponent field, the bias is $2^{k-1}-1$. IEEE 754 fixes the widths of these 3 fields.

Fractional bits are obtained by repeated doubling of the fractional part of the number, where each integer part produced becomes the next bit. For example: $0.92 \times 2=1.84$ (bit 1, keep 0.84), $0.84 \times 2=1.68(1)$, $0.68 \times 2=1.36(1)$, $0.36 \times 2=0.72(0)$, $0.72 \times 2=1.44(1)$, $\ldots$, so $0.92=0.1110101110000101 \ldots$

## Single Precision (float32, fp32)
![[fp32.png]]
- In fp32, the bias of the exponent field is 127
$$
x=(-1)^s \times 1.f\times 2^{e-127}
$$
- Values 0 and 255 are reserved for zero and subnormal numbers, and for $\pm  \infty$ and NaN
- Range is about $1.2 \times 10^{-38}$ to $3.4 \times 10^{38}$
- With a relative precision of $2^{-23} \approx 1.2 \times 10^{-7}$, about 7 significant decimal digits

## Double Precision (float64, fp64)
![[fp64.png]]
- In fp64, the bias of the exponent field is 1023
$$
x=(-1)^s \times 1.f\times 2^{e-1023}
$$
- Similarly, values 0 and 2047 are reserved for zero and subnormal numbers, and for $\pm  \infty$ and NaN
- Range is about $2.2 \times 10^{-308}$ to $1.8 \times 19^{308}$
- With a relative precision of $2^-52 \approx 2.2\times 10^{-16}$, about 16 significant decimal digits
- This is the default standard for python's float and NumPy
- Datacenter GPUs (NVIDIA A100 and H100, AMD MI300) have full float64 units and compute in it at about half their float32 speed. This is what makes them usable for simulations and linear algebra
- Consumer GPU's (GeForce, Radeon) compute in float64 at $1/32$ to $1/64$ of their float32 speed. 
- TPU's have no float64 hardware at all

# Narrower Formats
The above formats, though widely used in everyday applications, may not be as appropriate for machine learning tasks. We may prefer for the numbers to be less precise so that we may obtain more throughput out of them.
- `bf16`: $1+8+7$ bits, the first 16 bits of an fp32, which gives us the same range but roughly $2^{16}$ times coarser, giving about 3 significant decimal digits. This is the training format on most TPUs and recent GPUs.
- `fp16`: $1+5+10$ bits, range of $6\times 10^{-5}$ to $65504$, so overflow is a real risk
- `fp8`: E4M3, E5M2 and integer formats can be used for inference weights
