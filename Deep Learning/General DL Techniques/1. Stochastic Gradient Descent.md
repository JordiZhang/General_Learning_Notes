Gradient descent is an excellent algorithm widely used in machine learning, however as the number of samples increases, we run into bottlenecks. Although gradient descent is a linear complexity algorithm, in real life applications we may find datasets in the millions of samples. In such cases it is both slow to computer the entire gradient and in many cases impossible due to not being able to fit the dataset in memory. 

In an experiment for say the reaction of a new drug on humans, most accurate way to investigate this would be to test it on every human on the planet. This is clearly unfeasible so instead we approximate by experimenting on a small sample of the entire population. This is the principle behind Stochastic Gradient Descent. We subdivide the training dataset into batches and then perform gradient descent on each batch and update the weights accordingly. We are thus approximating the gradient of the loss from the entire dataset as the gradient of the loss calculated from the batch. Thus at each epoch, instead of calculating the gradients and updating the weights once, we instead have many of these updates depending on the batch size chosen.

Ideally, you want the batch size to be as large as possible, so that there is more information to be learned from, but in practice some models may only allow very small sizes due to computational or memory constraints. Although batch size is mostly arbitrary and up to the user, it is best practice to utilize powers of $2$ for hardware efficiency reasons. Memory is organized in blocks and powers of $2$ ensure proper alignment with said blocks. GPUs execute operations in blocks too that may be inefficient without using powers of $2$. Furthermore, some libraries are optimized for such sizes.

Technically what we discussed is actually called mini-batch gradient descent, as stochastic gradient descent specifically refers to when batch size is $1$. There are many naming conventions, but we will stick to what we have discussed here.
# Regularization
Due to it stochastic nature, performing SGD actually helps in regularizing a neural network to prevent overfitting. Intuitively, we can imagine this is case as we are approximating the loss of the dataset as the loss of a batch, thus the direction of the gradient is not exactly equal to what it would be for the full dataset. It can be thought of as adding some noise to the loss function. In fact many of the regularization techniques that we will discuss simply add noise somewhere during the training procedure.
