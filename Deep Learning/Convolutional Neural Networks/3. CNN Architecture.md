Convolutional neural networks were developed based on the traditional neural network. The main limitation of ANNs is that they struggle with the computational complexity required to compute image data. An image of size $28 \times 28$ requires a neuron in the first layer with $784$ weights, increasing image size to $64 \times 64$ requires $12,288$ weights. In the previous example, images are restricted to grayscale images. If we want to use colour images, this adds more dimensionality to the images, $64\times 64 \times 3$ for 3 colour channels, increasing the required weights even more. 

Another issue with ANNs is overfitting on image datasets. Say we are training a model to classify images as cats or dogs. We have two images, one where the cat is on the left and another where it is on the right. The ANN will have to separately learn the pattern for the cat being on the left vs being on the right, thereby overfitting on the dataset. Due to the large number of weights and therefore model complexity, overfitting becomes much more likely than the model learning the pattern for a cat. CNNs are designed to avoid this by using convolutions, as convolutions can be thought as pattern finders, in the discrete case. 
# Model
The modern CNN is derived from what is known as the LeNet-5 originally devised by Yann LeCun $et$ $al.$ It is comprised of 5 convolutional layers followed by a pooling layer after each convolutional layer, then the result is flattened and fed into 2 fully connected layers to classify the data. The modern general version of a CNN simply changes around activation functions, number of layers, pooling type, or even the order of layers (2 convolutional layers before every pooling layer)… Essentially remixes of this original model.

# Convolutional Layer
These can be thought of as analogous to the dense layer in a neural network, but in higher dimension. Instead of each neuron in the layer having a weight, we instead have each neuron in the layer having a separate learnable kernel/filter. Then each of the kernels are convolved with the input image giving a separate feature map (result of the convolution), which are then stacked. Similarly to a dense layer, an activation function is applied element wise to the resulting feature maps, thus giving the output. Although we are free to use different activations, in practice it is standard to use ReLU due to its performance. There are 3 hyperparameters that can be used to optimize a convolutional layer.
- Depth: This is just the number of neurons/learnable kernels in the layer, thus determining the number of feature maps. It is common to increase the depth by factors of 2 in subsequent layers. Intuition behind it is that we want to first learn small patterns like corners or edges, whereas subsequent layers will combine these to fully learn object parts, shapes or the like. The factor of 2 is arbitrary but it is commonly chosen as such due to computational efficiency.
- Stride: This determines how much overlap we want in the convolution. A stride of one is the typical convolution we think of. A stride of two would mean instead of moving the kernel one over, we move it two pixels over. For example, consider a $5 \times 5$ image convolved with a $3\times 3$ kernel. With stride one, this results in a feature map of size $3 \times 3$, where as with stride two, we get $2 \times 2$.![[conv_stride2.png]]
- Padding: How many layers of padding to add at the borders of the input. It is used to control the dimensionality of the resulting feature maps. See [[2. Convolution Types]] for more information.

Finally, in the same way as with dense layers, we can introduce a bias term:
$$
\text{Output}=\text{Bias}+ \text{Kernel}\star \text{Input}
$$
Note: For images, we usually use Conv2D layers, where 2D refers to two spatial dimensions, as the colour channel is not spatial. However for example, a video would count as having 3 spatial dimensions as we count time as one. Or perhaps we have voxels such as in medical imaging which have 3 spatial dimensions.
# Pooling Layer
Pooling layers aim to gradually lower the dimensionality of the feature maps and thus the complexity of the model. They help improve training efficiency and reduce overfitting by reducing the number of parameters for subsequent layers. This is done by downsampling using a kernel and a pooling function. This is done in a very similar manner to how convolutional layers work. We choose a kernel size, a stride and the pooling function. Then we pass the kernel over the inputted feature map based on the stride. Instead of doing a Hadamard product, we use the pooling function to summarize the section into a single pixel. In the below example we show average pooling with a $3\times 3$ kernel with a unit stride.
![[average_pool.png]]

As for pooling functions, there are many options applied to many different variations of the CNN architecture. The two main ones are the Max Pool and the Average Pool. Max Pool takes the maximum of the window, whereas Average Pool takes the average of the window.
# Dilation
Finally, we introduce the last hyperparameter for convolutional and pooling layers. To understand dilation better, it is instructive to first introduce the concept of the receptive field size. This is the number pixels in the input that are used in the calculation for a single pixel of the output. For a single convolutional layer, the receptive field size is just the kernel size. However, having more layers, we can see that the receptive field size increases further. With 2 layers (1 convolutional followed by a pooling one), with a $3\times 3$ kernel, the receptive field is $5\times 5$. 
![[receptive_field_size.png]]
Consider the MNIST dataset. If we are shown a single pixel of an image, we won't be able to figure out much. If instead we are shown a $10\times 10$ image, then we can like possibly figure out which digit the image is. Intuitively, the more of the image we are shown, the more likely we are able to figure out the right answer. Similarly, the receptive field can be thought of as how much the CNN can see, and thus how much spatial context it can process. Though this is a bit of a simplistic interpretation.

We can increase the receptive field size by increasing the kernel size or increasing the stride. However, increasing the kernel size increases computational cost, though increasing stride lowers it. Dilation is a technique to increase the receptive field size with no additional computational cost.
![[dilatited_convolution.png]]
Here we have shown a dilated convolution with a dilation factor of 2, where a factor of 1 corresponds to a normal convolution. Dilation thus introduces spacing between each of the kernel points.
# Connection to Dense Layer
The output of convolutional and pooling layers are 3D objects, but a dense layer expects a 1D vector as input. So how can we convert the 3D objects into 1D vectors? The simplest approach is to just flatten the vector into a 1D vector. This however, results in very large 1D vectors, so instead nowadays it is preferred to use methods such as Global Average Pooling or Global Max Pooling, where we take each of the feature maps then either take the average or the maximum of the feature maps. So we have:
$$
H\times W\times C \rightarrow 1\times 1 \times C
$$
Thus each of the feature maps is reduced to a single feature in the vector.
