# Inside the Python Interpreter
- CPython is the reference interpreter, which is a program written in C
- It compiles source to bytecode, for imported modules this is cached at `__pycache__/*.pyc` to speed up subsequent code runs
- Then a loop in C executes the bytecode instructions
Three kinds of code are available to a running interpreter:
- built-ins (`print, len, int, ...`), always loaded;
- the standard library, shipped with the interpreter (`os, sys, pathlib, json, subprocess, venv, ...` ), importable without installation;
- third-party packages (`numpy, matplotlib, ...` ), installed with pip into site-package

# Virtual Environments
- A virtual environment or venv should be created for each project you work on. Simply run the following in the project directory:
`python -m venv .venv`
- It is quite common to simply name the venv `.venv`. Then you to activate it:
`source .venv/bin/activate`
- To exit:
`deactivate`

# JupyterLab
JupyterLab is a browser front-end that should be installed in its own venv, then used for each project through the registered kernels. To do so, install `ipykernel` in the projects environment, then install the kernel:
`python -m ipykernel install --user --name attractor`

We can then use `jupyter kernelspec list` to see all the registered kernels.

Finally, if we want to open JupyterLab, we call the executable at its path:
`~/venvs/jupyter/bin/jupyter lab`

Alternatively, we can also use VSCode as a frontend.
