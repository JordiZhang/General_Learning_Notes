In standard stochastic gradient descent (SGD), we update parameters using a fixed learning rate. Choosing this learning rate is crucial: if it’s too large, training may fail to converge; if it’s too small, learning becomes painfully slow. To address this, we can consider varying the learning rate over time. We may start training using a larger learning rate to quickly get close to the minima, then reduce the learning rate for convergence. In this section, we will discuss some common strategies to do so.

Simplest form of varying learning rate is the step decay. We multiply the learning rate by some constant after some number of iterations or epochs. For example, every 50 epochs we halve the learning rate. Some other decay-based methods are listed below:
- Exponential Decay
$$
\eta(t)=\eta_{0}\exp(-\lambda t)
$$
- $1/t$ decay
$$
\eta(t)=\frac{\eta_{0}}{\lambda t+1}
$$
- $1/\sqrt{ t }$ decay
$$
\eta(t)=\frac{\eta_{0}}{\sqrt{ t }}
$$
Another way of varying the learning rate is simply doing it manually. Run a few epochs and decide if you want to lower it or increase it at your convenience. Clearly however, this is tedious and adds even more hyperparameters to think about. Even choosing which decay to use is also a hyperparameter. 
# AdaGrad
In stochastic gradient descent, we typically use a single global learning rate for all parameters. However, different parameters can behave very differently during training. Some parameters may receive large, frequent gradients, while others are updated only rarely. Using the same learning rate for all of them can be inefficient as frequently updated parameters may require smaller steps to avoid oscillation, while infrequent ones would benefit from larger updates. Thus we introduce the AdaGrad algorithm.

The theoretical statement of AdaGrad is quite complicated and comes from online convex optimization, so we won't go over how to derive it but only its intuition. In fact AdaGrad is not a single algorithm, but a family of them derived using the methodology described in the original paper by [Duchi et. al.](https://www.jmlr.org/papers/volume12/duchi11a/duchi11a.pdf) However, there is a widely accepted standard gradient descent AdaGrad algorithm (section 1.1) that is the one implemented in most machine learning libraries. 
$$
\begin{align}
g_{t}&= \nabla_{W} L_{t} \\
G_{t}&= \sum_{\tau=1}^tg_{\tau}^2=G_{t-1}+g_{t}^2 \\
W_{t}&=W_{t-1}-\frac{\eta}{\sqrt{  G_{t}+\epsilon}}g_{t}
\end{align}
$$
The division is done element wise and so is $g_t^2$, thus there is a different effective learning rate for each of the parameters. $G_{t}$ is also known as the cache. Note that $\epsilon$ is a modification of the algorithm to avoid divisions by zero, usually a small value. Some implementations (most) do not include $\epsilon$ in the square root so its good to check before hand. For example PyTorch uses this convention (doesn't include in the square root) and their default value is $10^{-10}$.

Empirically, AdaGrad decreases the learning rate too aggressively, so it would approach $0$ when there was still more learning to be done. The reason for this is that $G_t$ grows too fast, so the solution to this is to decrease it after each update. Instead of taking $G_t$ to be the sum of the gradients squared, we define it as a moving average (check Adam for more detail) of the gradients squared.
$$
G_{t}=\alpha G_{t-1}+(1-\alpha)g_{t}^2
$$
where $\alpha$ is the decay factor, usually around $0.9$. This modification is called RMSProp originally devised by Hinton et. al. This type of modification is also referred to as the leaky version of the algorithm, i.e. Leaky AdaGrad.

When implementing either of these algorithms, one thing to consider is the initial value of the cache. Naively we might think initializing these to $0$ is appropriate as we normally initialize the gradients to $0$. However, this leads to a very small denominator, so the effective learning rate becomes massive. One solution to this is to instead initialize the cache to $1$. This way the first update becomes approximately $\Delta W=\eta g_{t}$. Different libraries may have different initializations so this should be checked too.
